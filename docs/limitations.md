# 알려진 제한사항

- 실제 .NET Framework 4.6.2·VS2019·DevExpress 업무 솔루션은 아직 검증하지 않음. 참조 어셈블리, 외부 DLL, 사용자 정의 targets 확인 필요.
- MSBuildWorkspace는 프로젝트 평가/디자인 타임 빌드를 수행한다. 분석기는 업무 소스를 수정하지 않지만 MSBuild가 obj 등 중간 산출물을 생성할 수 있다.
- 최신 .NET의 MSBuildLocator가 VS2019 MSBuild를 선택한다고 가정하지 않는다. 필요하면 향후 레거시 분석 프로세스를 별도로 검토.
- Reflection, dynamic, 런타임 문자열·설정·DI는 실제 실행 관계 확정 불가.
- 메서드/생성자 호출과 이벤트 처리기 등록을 추적한다. 모든 속성 접근·연산자·delegate 호출·런타임 이벤트를 포괄하지 않는다.
- WCF 프록시와 원격 서버 구현은 자동 연결하지 않음. 계약 경계가 확인되면 경고를 반환하고 근거 없는 이름 매칭은 하지 않음.
- 인터페이스 구현은 DispatchCandidate로 표시. 모든 가상 호출의 런타임 override를 완전하게 추적하지 않음.
- 등록된 DB 래퍼의 상수 인자와 DbCommand 초기화 후보를 분석한다. 변수의 전체 데이터 흐름, 런타임 문자열 조합, SQL 문자열 내부의 EXEC는 지원하지 않음.
- SqlDependency는 직접 참조를 연결하며 프로시저 호출은 제한 내에서 추가 탐색한다. 뷰·함수의 간접 참조, 동적 SQL, 임시 객체, synonym 대상은 확인 필요.
- LiveDatabase의 READ/WRITE는 Unknown. SqlFiles는 INSERT 및 읽기/변경 후보를 문법으로 구분하며 별칭·컬럼의 의미 바인딩은 완전하지 않음.
- actual SQL Server 정상 조회 경로는 접속정보 미제공으로 검증하지 않음. DB 미설정 및 연결 실패와 모의 의존성 조합은 검증.
- 프로시저 정의는 includeDefinition=true일 때만 반환. 소스와 배포 DB의 버전 일치 확인 필요.
- C# 분석 요청 전 파일/프로젝트/참조 변경을 대조하고 전체 재로딩. 대형 솔루션 성능 및 외부 사용자 MSBuild 입력 전체 영향은 검증 필요. 재로딩 후 새 ID로 조회.
- 한 프로세스에서 활성 솔루션은 하나. MCP 분석 요청은 직렬화하여 탐색 중 스냅샷 변경 방지.
- 일부 프로젝트 실패는 Partial과 진단으로 반환. 결과 없음은 호출 없음의 증거가 아님.
- 문자열 검색은 추가 검색 루트를 포함한 디스크 파일을 읽음. 읽을 수 없는 경로는 생략될 수 있음.
- Codex 실제 등록 및 대형 솔루션 성능 검증은 확인 필요.
