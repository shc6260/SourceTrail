# 소스 변경 감지

2026-11-19 파일·구문 색인으로 전환했습니다. 아래 과거 검증은 이전 의미 분석 구현의 기록이며 현재 성능 수치로 사용하지 않습니다.

- 설정을 생략한 라이브러리 기본값은 WatchCodeFiles=false입니다. 배포 예제·신규 설치 프롬프트는 true와 30초 주기를 권장합니다. 감시 오류 시 전체 대조로 복귀합니다.
- 실제 소스·리소스·직접 읽는 프로젝트 메타데이터만 기본 추적합니다. DLL·obj 빌드 입력·상위 NuGet/MSBuild 설정은 추적하지 않습니다.
- 변경 파일만 다시 파싱하고 원본이 같은 선언 ID는 재사용합니다. 감시기 교체 중 버전은 새 감시기에 전달하지 않습니다.
- 저장 직후 알림 전 첫 요청의 최신성은 보장하지 않으므로 요청마다 즉시 대조해야 하면 false를 사용합니다. 명시적 재대조에는 reload_solution을 사용합니다.

설치·색인 생성·실행 순서와 효율적인 조사 프롬프트는 [메인 README](../README.md)에 있습니다.

## 실제 MCP 왕복 측정 — 2026-11-19

수정한 Release 서버를 기존 등록 MCP와 별도 프로세스로 실행했다. 같은 DLL에서 `WatchCodeFiles=false`와 `true`만 바꿨으며, 준비한 동일 디스크 색인을 서로 다른 폴더에 복사했다. 두 모드는 같은 스냅샷을 복원했다. 색인 입력은 외부 참조 등을 포함해 7,798개, C# 상태는 Partial이었다. DB 모드는 SqlFiles이며 실제 DB 접속 없음.

프로세스 초기 연결·솔루션 로딩·색인 준비·도구별 예열 2회를 제외하고, 세 도구를 각각 모드별 5회씩 순서를 교대해 호출했다. 아래는 실제 stdio `tools/call` 요청 전송부터 응답 수신까지의 중앙값이다.

| 도구·대상 | 기존 매 요청 검사 모드 | 새 감시 모드 |
|---|---:|---:|
| find_database_calls — 접수 기본정보 | 200.23ms | 0.94ms |
| find_database_calls — 검사오더 | 202.24ms | 1.08ms |
| find_symbol — 서버 구현 후보 | 211.89ms | 12.30ms |

모든 대응 응답의 원문이 같았다. 측정 30회 중 기존 모드 15회 모두 전체 파일 대조 telemetry가 있었고, 감시 모드 15회에서는 없었다. 전체 측정 구간은 약 3.17초로 30초 대조 주기 안이며 소스 변경이 없는 상태다. 변경 발생·주기 만료 시의 재검사/재분석, 최초 로딩, AI 판단을 포함한 전체 조사 시간으로 일반화하지 않는다. 기존 Partial/미해결 호출을 해결했다는 의미도 아니다.

측정 준비 중 샌드박스의 BuildHost 파이프 접근 제한과 준비 캐시 복사 단계의 실행 중단이 있었다. 로컬 프로세스 통신을 허용하고 동일 준비 캐시를 복사한 뒤 측정 구간을 처음부터 수행했다. 기존 MCP 등록/설정/실행본은 교체하지 않았으며, 비교용으로 생성한 자식 MCP만 종료했다.

계측 스크립트와 원시 응답·표본·stderr 로그는 작업공간의 `implementation-results/mcp-freshness-probe-2026-11-19.cjs` 및 `implementation-results/mcp-freshness-roundtrip-2026-11-19-verified/`에 보관했다.

## 변경 없는 반복 요청의 검사 비용

이 PC에서 Phase2 솔루션 폴더 및 상위 설정의 입력 7,555개를 대조했다. 외부 프로젝트/참조의 별도 입력 목록은 전달하지 않았다. 첫 해시 수집·감시 준비 및 각 방식의 예열 1회는 제외하고, 순서를 교대해 각 5회 측정했다.

| 검사 경로 | Release 중앙값 |
|---|---:|
| 기존 전체 목록·파일 상태 대조 및 내용 동일성 확인 | 431.4577ms |
| 변경 알림·주기 확인 후 전체 대조 생략 | 0.0012ms |

후자는 생략 여부를 결정하는 분기 비용만 측정한 값이다. 타이머 오차를 고려해 사용자 요약에서는 0.01ms 미만으로 표시한다. **MCP 전체 왕복·캐시 결과 역직렬화·Roslyn 의미 분석·AI 판단 시간이 아니다.** 다른 PC의 7,804개/70.7ms 측정과 입력 범위·환경이 달라 직접 비교하지 않는다. 변경 발생·감시 실패 시의 전체 대조/재로딩 시간도 이 표에 포함되지 않는다.

Release 표본(ms): 전체 `[442.7543, 426.6270, 439.6978, 431.4577, 428.7659]`, 감시 `[0.0028, 0.0002, 0.0013, 0.0001, 0.0012]`. 측정 종료 시 감시 상태는 추가 검사 불필요였다.

기존 입력 대조는 파일 메타데이터가 같으면 저장된 해시를 재사용한다. 프로세스 밖에서 알림까지 누락된 채 크기·시각이 모두 같게 복원된 변경을 주기 검사만으로 반드시 검출한다고 보장하지 않는다. 이 제한은 기존 메타데이터 기반 검사에도 있다.
