# 구조와 동작 원리

SourceTrail은 파일·C# 구문 색인과 로컬 SQL 파일 검색을 수행합니다. C# 컴파일, MSBuildWorkspace, BuildHost, 참조 어셈블리 로딩은 사용하지 않습니다. Roslyn 패키지는 파일 단위 구문 파서에만 사용합니다.

설치·일괄 생성·첫 요청·캐시 재사용의 흐름과 사용 프롬프트는 [메인 README](../README.md)에 모았습니다.

## 검색 순서

아래는 화면 동작에서 시작하는 경우입니다. 문구·알려진 식별자·프로시저를 조사할 때는 [사용 지침](usage-guidelines.md)에 따라 해당 도구에서 시작합니다.

1. `find_ui_actions`: 화면·메뉴·버튼 문구와 Designer 바인딩으로 후보를 찾습니다.
2. 핸들러·저장 메서드 원문에서 실제 호출명과 계약을 확인합니다.
3. `find_symbol`은 확인한 이름의 선언 후보, `get_symbol_overview`는 선언 구조, `search_text`는 실제 파일의 문자열 위치를 찾습니다.
4. `find_database_calls`: 선택한 메서드 하나의 명령 설정·Adapter 매핑 후보와 다음 호출 키워드를 반환합니다. 재귀 호출 추적과 자동 WCF 연결은 하지 않습니다.
5. `find_sql_object`, `analyze_procedure`: 로컬 SQL 정의와 직접 참조를 조회합니다.

## 색인과 변경 감지

- C# 선언은 파일 경로·내용 해시·구문 위치로 식별합니다. 타입·매개변수 표기는 원문 기반이며 오버로드 바인딩은 하지 않습니다.
- 캐시는 명시적인 `source-syntax-2-lazy` 규격 버전으로 구분합니다. 실행 DLL의 무관한 재빌드로 무효화하지 않습니다. 모델·추출 규칙 변경 시 버전을 올려야 합니다.
- 원본 파일 추가·수정·삭제 및 직접 읽는 csproj의 DefineConstants 변경을 반영합니다. 파일 목록은 먼저 준비하고 선언은 필요할 때만 파싱합니다. 이미 읽은 파일은 재사용하고 변경 파일만 다시 파싱합니다.
- 참조 DLL, NuGet·MSBuild 상위 설정은 기본 검사에서 제외합니다. csproj는 메타데이터·직접 기재된 상수를 읽는 데만 사용하며 조건·imports를 평가하지 않습니다.
- `WatchCodeFiles=false`는 요청 경계에서 원본 대조, `true`는 알림과 주기적 대조를 사용합니다. 알림 지연 때문에 저장 직후 즉시 반영은 보장하지 않습니다.
- 감시 오류는 전체 대조로 복귀합니다. 취소·실패한 색인은 기존 스냅샷을 덮어쓰지 않습니다.
- UI 문구 색인과 SQL 정의 색인은 각각 준비·재사용됩니다. SQL은 기존 ScriptDom 파서와 파일 변경 대조를 유지합니다.

## 텍스트 검색 경로

2.0.1의 `search_text`는 선언 색인과 별개로 현재 디스크 파일을 검색합니다. 파일 목록과 검색 범위 확인 → rg로 후보 파일 선택 → 기존 .NET 읽기로 원문 검증 → 전체 건수 집계와 페이지 반환 순서입니다. 색인 준비·컴파일은 호출하지 않습니다.

rg는 백그라운드 자식 프로세스로 실행합니다. 파일명은 NUL 구분으로 받고 셸을 거치지 않는 인수 배열을 사용합니다. UTF-16/32 BOM 파일과 파일 링크도 기존 읽기로 확인하며 디렉터리 링크는 기존처럼 따라가지 않습니다. 결과는 기존 파일 순서로 모으므로 rg의 출력 순서가 페이지 순서를 바꾸지 않습니다.

rg 부재·실행 오류·30초 제한 시에는 기존 검색으로 대체하고, 사용자 취소 시에는 프로세스를 종료해 취소를 전달합니다. `Analysis.UseRipgrep`과 `Analysis.RipgrepPath`는 [등록 및 설정](codex-registration.md)을 참고하세요. 내부 로그에는 대기·파일 열거·rg 후보 검색·원문 검증 시간을 나눠 남깁니다.

[2.0.1 검증 결과](performance-results.md)는 텍스트 검색 수정 전후와 고정 작업의 과거 직접검색 비교를 구분합니다.

## 결과의 의미

`Ready`는 소스 색인이 준비됐다는 뜻입니다. 컴파일 성공을 뜻하지 않으며 CompilationErrors는 미평가(null 또는 생략)입니다. 구문 진단은 실제 읽은 파일에만 적용됩니다. 파일명을 우선한 선언 검색은 전체 범위를 탐색하지 않았음을 경고에 표시합니다. 이름 참조와 DB 명령은 후보입니다. 원문 대조 없이 실제 실행·런타임 연결로 승격하지 않습니다.

전체 forward/reverse 그래프, WCF 호스트 자동 재탐색, compact 그래프 출력, LiveDatabase 모드는 제거했습니다. SQL 소스와 C# 소스는 서로의 작업 전체가 끝나기를 기다리는 전역 잠금 대신 각 분석기의 상태 잠금을 사용합니다.
