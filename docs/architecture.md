# 구조와 구현 상태

## 구성
- MCP: 도구 입력, 설정, stderr 로깅. 분석 요청을 직렬화하여 재로딩과 흐름 탐색의 스냅샷 충돌 방지.
- Core: 공통 결과 모델, 분석기 계약, 깊이·노드·순환 제한, 양방향 흐름 조합.
- Roslyn: MSBuildWorkspace, 선언 심볼 캐시, SymbolFinder 참조, 실제 호출·이벤트 등록 분석, 외부 DB 래퍼 규칙.
- SqlServer: DatabaseAnalyzer 모드 선택, ScriptDom SQL 파일 분석·내용 해시 캐시, 또는 고정된 DB 메타데이터 SELECT. 연결정보는 외부 설정.

## 근거와 정합성
심볼 참조와 호출을 구분한다. 문자열 후보, DB 래퍼 계약, 명령 초기화, 인터페이스 구현 후보, SQL 의존성은 서로 다른 관계 유형이다. 실행·저장 성공으로 해석하지 않는다. LiveDatabase의 READ/WRITE는 Unknown, 파일 모드는 문법 근거와 변경 후보를 반환한다. 전체 소스는 반환하지 않는다.

## 캐시와 수명
활성 솔루션 하나를 유지한다. Roslyn Solution/Compilation을 재사용하고 선언 심볼·프로시저 후보·요청 주변 관계를 메모리에 캐시한다. 재로딩 시 캐시와 ID를 교체하며 로딩 실패 시 기존 스냅샷을 보존한다. 기본 깊이 5, 노드 200, 결과 100. 제한 도달 시 truncated와 경고를 반환한다.

## 확인한 검증
.NET 10.0.401에서 전체 빌드 경고 0·오류 0. xUnit 회귀·SQL 파일 캐시 테스트 통과. 가상 WinForms와 오류 프로젝트로 로딩·심볼·참조·호출·이벤트·프로시저 후보·양방향 흐름·실패·재로딩 검증. scripts/Smoke-Mcp.ps1에서 16개 도구를 MCP stdio로 호출해 검증한다. SQL 테이블 의존성 조합 테스트는 모의 결과이며 실제 DB 조회와 구분한다.

## 실제 프로젝트 적용 전 확인
- 코드 흐름 확인: 실제 DB 래퍼의 타입·메서드·프로시저 인자 위치를 규칙으로 등록.
- DB 스크립트 대조: 소스 버전과 조회 대상 DB의 정의 일치 확인. 운영 변경 실행 제외.
- 분석 환경 확인: .NET Framework 4.6.2 참조 어셈블리·DevExpress·사용자 정의 targets 확인. 현재 PC의 참조 어셈블리 목록에는 v4.6.2가 없음.
- 검증 방법 확인: 실제 화면 이벤트부터 DB까지 대표 사례를 원문과 대조. WCF 원격 구현, 동적 SQL 및 간접 의존성은 확인 필요.

Domain Map, WCF 원격 계약 매핑, 뷰·함수 간접 탐색 및 레거시 분석 프로세스는 후속 확장 범위다.

SQL 자료 선택·캐시·갱신과 C# 디스크 캐시 검토 결과는 [sql-sources.md](sql-sources.md)에 기록했습니다.
