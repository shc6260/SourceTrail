# 2.0.1 변경과 검증 결과

측정일은 2026-11-20입니다. 아래 수치는 한 로컬 환경의 결과이며, 서로 다른 실험의 시간을 합치거나 전체 AI 조사 성능으로 해석하지 않습니다. 원시 측정과 내부 프로젝트 근거는 로컬에 보관하고 이 문서에는 집계와 조건만 공개합니다.

## 변경 범위

`search_text`는 기본적으로 ripgrep으로 후보 파일을 찾고, 해당 파일을 기존 .NET 읽기로 검증합니다. 원문 인코딩 처리, 줄·UTF-16 열 번호, 미리보기, 전체 건수와 페이지 순서를 유지합니다. `find_symbol`의 메서드·클래스 선언 조회, UI 색인과 SQL 색인은 기존 방식을 사용합니다.

rg가 없거나 실행에 실패하면 기존 .NET 텍스트 검색으로 대체합니다. `Analysis.UseRipgrep=false`로 기존 검색을 선택하거나 `Analysis.RipgrepPath`로 실행 파일을 지정할 수 있습니다. Windows에서는 확장자 없는 다른 플랫폼 바이너리 대신 `rg.exe`를 찾습니다.

## 텍스트 검색: 수정 전후 비교

기존 2.0.0과 수정 2.0.1을 별도 stdio 프로세스로 실행했습니다. 같은 입력을 순차·교대로 호출하고 첫 표본 이후 각 3회 중앙값을 계산했습니다. OS 파일 캐시는 초기화하지 않았으며, 프로세스 연결과 준비 시간은 아래 표에서 제외했습니다. AI 판단·답변 작성은 측정하지 않았습니다.

| 검색 조건 | 기존 2.0.0 | 수정 2.0.1 |
|---|---:|---:|
| 전체 폴더의 문자열 검색, 결과 171건 전부 반환 | 4.915초 | 0.855초 |
| 같은 검색의 두 번째 페이지 35건, 전체 건수 171건 | 4.941초 | 0.823초 |
| 전체 폴더 검색, 결과 0건 | 3.081초 | 0.810초 |
| 알려진 폴더의 문자열 검색, 결과 35건 전부 반환 | 0.014초 | 0.034초 |

모든 반복에서 파일·줄·열·미리보기·전체 건수·offset·limit·truncated가 일치했습니다. 전체 171건 검색의 관측 시간은 약 83% 줄었습니다. 범위가 작은 검색에서는 rg 프로세스 실행 비용으로 더 오래 걸렸습니다. limit을 조기 종료 조건으로 바꾸어 얻은 결과가 아닙니다.

## 고정 5단계: 과거 직접검색 기준과 참고 비교

고정 작업은 UI 근거 7개 → 원문에서 호출명·계약 확인 → WCF 선언 4개 → 서버·DB 지점 3개 → SQL 정의 위치 1개입니다. 공통 원문 읽기와 현재 API에 필요한 후속 조회를 모두 포함합니다.

직접검색은 다시 실행하지 않았습니다. 2026-11-19의 반복 3회 중앙값을 기준으로, 2.0.1의 첫 유효 실행 이후 3회 중앙값을 비교했습니다. 과거와 현재의 호출명·계약 선언 내용·DB 대상은 일치했고 일부 소스 줄 번호는 이동했습니다. 현재 측정 중 확인 대상 파일의 해시는 유지됐습니다. 동일 소스 스냅샷의 통제 A/B가 아닌 과거 기준과의 참고 비교입니다.

| 단계 | 과거 직접검색 | 현재 MCP 2.0.1 |
|---|---:|---:|
| 화면·버튼 찾기 | 1.118초 | 0.186초 |
| 원문에서 호출명 확인 | 0.678초 | 0.802초 |
| WCF 선언 확인 | 0.411초 | 0.046초 |
| 서버·DB 연결 확인 | 0.779초 | 0.741초 |
| SQL 정의 위치 | 0.423초 | 0.001초 |
| 전체 고정 작업 | 3.416초 | 1.771초 |

각 단계와 전체는 각각 중앙값이므로 행 합계가 전체와 같지는 않습니다. 이 고정 작업은 과거 기준보다 약 48% 짧게 관측됐습니다. AI 판단이 포함된 전체 조사 시간이나 rg 변경만의 개선율을 뜻하지 않습니다.

연결·도구 목록 준비는 0.339초, 로딩을 포함한 첫 유효 실행은 17.947초로 별도 기록했습니다. 첫 유효 실행도 기존 캐시를 사용한 조건이므로 최초 설치·완전 cold start가 아닙니다. 첫 표본을 반복 중앙값에 섞지 않았습니다.

엄격한 줄 위치 비교 실패와 제한 환경의 AppData 캐시 쓰기 거부로 인한 실패는 별도로 보존했습니다. 실제 MCP와 같은 캐시 쓰기 권한으로 재실행한 뒤 4회 모두 같은 조회 대상을 확인했습니다. 현재 32회 MCP 호출과 8회 공통 원문 읽기에서 오류는 없었습니다.

### 이전 측정과의 구분

2.0.0의 과거 고정 작업 중앙값은 1.869초, 같은 실험의 직접검색은 3.416초였습니다. 당시 첫 표본은 각각 6.366초와 3.932초였습니다. 과거 v12의 1.045초는 또 다른 버전의 값입니다. 이 수치들을 현재 2.0.1의 첫 실행·캐시 조건과 합산하지 않습니다.

## 기능 검증과 해석 범위

전체 테스트는 62개 통과, 실패 0개, 심볼릭 링크 생성 권한이 필요한 1개는 건너뛰었습니다. 관련 [회귀 테스트](../tests/SourceTrail.Tests/RipgrepTextSearchTests.cs)는 한글·이모지 열 번호, UTF-8/16/32 BOM, 숨김·gitignore 파일, 제외 폴더·확장자, 추가 루트, 중복·페이지 처리, 리터럴·대소문자, 실행 파일 탐색과 실패 대체를 확인합니다. 링크 테스트는 권한이 있는 환경에서 추가 검증이 필요합니다.

일반적인 임의 질문의 전체 조사 시간, 정확도, 토큰 사용량과 청구 비용의 개선은 이 실험으로 확정하지 않습니다. 기존 직접검색 기준은 질문·범위·반환 근거·시간 경계가 맞을 때 재사용하며, 맞는 과거 기준이 없는 작업은 별도 참고 또는 새 측정으로 구분합니다.
