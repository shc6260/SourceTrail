# SourceTrail 사용 지침

SourceTrail을 사용하는 조사에서 필요한 항목만 적용한다. 프로젝트의 역할·쓰기·DB 접근 제한을 유지하며, 검색 도구 선택이 그 제한을 해제하지 않는다.

## 시작 도구 선택

조사 전에 질문의 범위와 완료 조건을 정한다. 모든 질문에 버튼 검색이나 전체 호출 경로 추적을 요구하지 않는다.

| 알고 있는 정보 | 시작 방법 |
|---|---|
| 화면의 버튼·동작 | `find_ui_actions`에 화면과 동작을 분리한 짧은 문장 전달. 예: `접수 저장` |
| 화면 문구·목록 항목 | 알려진 폴더·확장자로 좁힌 `search_text` |
| C# 파일·식별자 | 필요한 원문을 읽고 `get_symbol_overview` 또는 `find_symbol` |
| 프로시저 이름 | `find_sql_object`, 필요한 경우 `analyze_procedure` |
| 프로시저를 부르는 곳 | `find_procedure_usage` (C# 후보와 `sqlCallers` SQL 호출처를 함께 반환) |
| 테이블·뷰를 쓰거나 읽는 SQL | `find_sql_references` (INSERT/UPDATE/DELETE/SELECT/EXEC 구분) |
| 클래스의 상속 관계 | `find_symbol`로 선언 ID를 얻은 뒤 `get_symbol_overview`의 `baseTypes`·`derivedTypes` |

## 조회 순서

1. MCP로 후보를 찾는다.
2. 필요한 원문에서 실제 호출명·계약·인수·조건을 확인한다.
3. 확인한 이름으로 MCP를 다시 조회하고 필요한 다음 연결만 따라간다.
4. 요청한 근거를 확보하면 종료한다. 조사 범위·진행 방식 변경은 먼저 묻는다.

이름이나 디렉터리를 추정하여 선검색하지 않는다. 위치를 모르면 화면·파일 후보부터 확인한다. 서비스 호출 연결은 호출부와 계약·구현을 대조하고, 저장 조사에서 필요한 경우 인수 타입·조건부 분기·Added/Modified/Deleted·개별/일괄 방식을 확인한다.

## 도구별 주의사항

- `find_symbol`: 확인한 식별자·전체 이름을 전달한다. 반환된 소스 ID는 그대로 후속 호출에 사용한다. 파일명 우선 범위 경고가 있으면 전체 선언을 찾았다고 단정하지 않는다.
- `get_symbol_overview`: 이미 알고 있는 C# 파일 절대 경로를 사용할 수 있다. 상속 클래스(`derivedTypes`)는 타입 선언 ID로 호출할 때 나온다. 멤버가 많으면 `memberQuery`로 이름을 좁힌다.
- `search_text`: 코드의 실제 문자열을 사용하고 알려진 `directory`와 허용 `extension`으로 좁힌다. 일반 텍스트 검색에 화면·동작을 임의로 붙인 `접수저장` 같은 조합어를 넣지 않는다.
- `find_database_calls`: 선택한 메서드 하나만 `symbol`과 `limit`으로 조회한다. `maxDepth`/`maxMethods`와 자동 전체 그래프 추적은 사용하지 않는다. `methodCandidates`와 원문에서 다음 호출을 선택한다. 명령 설정·Adapter 매핑은 실행 증거가 아닌 후보다.
- `find_reference_candidates`: 추가 사용처 조사가 필요한 목적·범위를 먼저 설명하고 묻는다. 이름 사용처 후보를 실제 심볼 참조·오버로드 바인딩으로 단정하지 않는다.
- `find_sql_object`/`analyze_procedure`: 코드 경로 조사에서는 원문으로 연결을 확인한 프로시저만 조회한다. 질문에 프로시저가 명시되면 정의 조회에서 시작할 수 있다. 위치만 필요하면 `find_sql_object`의 `locationsOnly=true`를 사용한다. 본문이 필요하면 정의와 직접 참조를 확인한다. SQL 내부 호출을 무조건 재귀 확장하지 않는다.

## 중복 조회와 색인 준비

- 원문은 필요한 구간만 읽고 확보한 파일·줄 번호·결과를 재사용한다. 응답에 필요한 정의와 위치가 모두 있으면 위치를 별도 조회하지 않는다.
- 이미 확인한 연결을 전체 이름 사용처 검색으로 재검증하지 않는다.
- `truncated`/`unresolved`/`Partial`은 확인 필요로 표시한다. 부족한 필수 근거는 같은 범위에서 보완하고, 미검색 범위를 없다고 단정하지 않는다.
- 일반 조회를 위해 `prepare_indexes`/reload/refresh를 반복 실행하지 않는다. 색인 준비·갱신이 필요하면 [설치와 색인 안내](../README.md)를 따른다. 색인 상태만으로 원본 최신성을 보증하지 않는다.
- SQL은 로컬 `SqlFiles`로 확인한다. 이 문서는 실제 DB 접속·SQL 실행을 허용하지 않는다.

## 결과 전달

기본 결과는 채팅에 결론, 필요한 파일·줄 번호, 확인한 연결, 후보와 확인 필요사항을 간단히 정리한다. 별도 보고서 파일과 상세 시간 계측은 요청할 때만 작성한다. 비교 테스트의 방식·완료 기준·계측 항목은 해당 테스트에서 따로 합의한다.

## 프로젝트 지침에 연결하기

프로젝트 지침에는 아래처럼 짧게 연결한다. Codex는 `AGENTS.md`, Claude Code는 `CLAUDE.md`, 다른 클라이언트는 해당 도구가 읽는 지침 파일을 사용한다. 로컬에 설치한 저장소 경로로 바꾸고, 해당 도구를 사용할 때 상세 문서를 읽는다.

```markdown
- SourceTrail을 사용하는 조사에서는 설치된 저장소의 `docs/usage-guidelines.md`를 먼저 읽는다.
- MCP 후보 → 필요한 원문에서 실제 이름 확인 → MCP 재조회 순서로 진행한다.
- 확보한 근거를 재사용하고 요청 범위에서 종료한다. 결과는 채팅에 간단히 답하며 보고서 파일·상세 계측은 요청할 때만 작성한다.
```
